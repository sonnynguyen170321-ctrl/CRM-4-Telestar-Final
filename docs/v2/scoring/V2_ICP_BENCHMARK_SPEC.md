# V2 ICP Benchmark Spec

Status: **V2.ICP-BENCH0R docs-only repair**
Runtime status: **benchmark scripts are not implemented in this phase**

## 1. Purpose

This spec defines benchmark truth, row shape, split policy, multi-ICP handling, and unmapped exclusions for ICP scoring review.

It does not authorize runtime scoring code, benchmark runners, live AI calls, schema, API, UI, or V1 changes.

## 2. Benchmark Truth Hierarchy

```txt
AI agent assessment = advisory signal
Deterministic engine assessment = candidate assessment
Human final label = benchmark truth
```

Weak benchmark output is not production truth. Human-final labels are required before claiming production accuracy.

## 3. Live AI Prohibition

Benchmark scripts must not call live AI providers.

Fields for ChatGPT, Claude, and Gemini assessments are imported or human-filled advisory data only.

No live OpenAI, Claude, or Gemini calls are allowed in benchmark runs.

## 4. Benchmark Splits

```txt
GOLDEN_PASS_FAIL
AMBIGUOUS_REVIEW
RULE_IMPROVEMENT
UNMAPPED_EXCLUDED
```

Split meanings:

- `GOLDEN_PASS_FAIL`: human-final truth is stable enough for pass/fail scoring agreement.
- `AMBIGUOUS_REVIEW`: valid review case; should not count as a hard false positive/false negative.
- `RULE_IMPROVEMENT`: human review found rule gaps or calibration needs.
- `UNMAPPED_EXCLUDED`: source pipeline is known but intentionally excluded from scoring agreement.

## 5. Benchmark Row Contract

```ts
type IcpBenchmarkCase = {
  benchmarkCaseId: string;

  companyName: string;
  website?: string;
  industry?: string;
  country?: string;
  employeeRange?: string;
  contactTitle?: string;
  contactLocation?: string;

  subPipeline: string;
  canonicalIcpId: string | null;

  benchmarkSplit:
    | "GOLDEN_PASS_FAIL"
    | "AMBIGUOUS_REVIEW"
    | "RULE_IMPROVEMENT"
    | "UNMAPPED_EXCLUDED";

  agentAssessments?: {
    chatgpt?: AgentAssessment;
    claude?: AgentAssessment;
    gemini?: AgentAssessment;
  };

  deterministicAssessment?: IcpAssessment;

  humanFinalQualification?: "QUALIFIED" | "NEEDS_REVIEW" | "UNQUALIFIED";
  humanFinalReason?: string;
  ruleAdjustmentNeeded?: boolean;
  ruleAdjustmentNote?: string;
};
```

`AgentAssessment` is advisory-only imported data. It must not be generated by benchmark scripts.

## 6. Multi-ICP Assessment Policy

Multi-ICP assessment is acknowledged but runtime implementation is deferred.

A source row can generate multiple benchmark rows when intentionally mapped to multiple ICPs.

Examples:

```txt
Chainwire -> Chainwire Crypto + Chainwire Cyber
Stratova -> Stratova CXO + Stratova GCP Event
1C -> Document Management + Company Management + ERP
```

Required generated assessment fields:

```txt
canonicalIcpId
icpName
icpTrack
sourceSubPipeline
multiIcpGroupId if generated from same source row
```

When multi-ICP expansion is not implemented, mark the case with `multi_icp_assessment_deferred`.

## 7. Unmapped Policy

Known unmapped pipelines must be explicitly excluded:

```txt
GHS
FastNetMon
Choys
Teamflect
GMO
N7
SoraSo
ZetNet_Michael
```

Policy:

```txt
benchmarkSplit = UNMAPPED_EXCLUDED
canonicalIcpId = null
benchmarkPolicy = EXCLUDE_UNMAPPED
```

Excluded rows must not count toward:

```txt
scoring agreement
qualified rate
false positives
false negatives
```

## 8. Required Agreement Metrics Later

Future benchmark harnesses may calculate:

```txt
overall agreement rate
QUALIFIED precision against human-final labels
UNQUALIFIED precision against human-final labels
NEEDS_REVIEW rate
false positive rate
false negative rate
unmapped excluded count
rule improvement count
```

This phase does not implement the harness.
